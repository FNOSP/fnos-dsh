## 需求背景

FPK 的应用版本此前由 `pnpm run version -- project <patch|minor|major>` 通过语义化档位递增，前三段随每次发布变化。用户要求改为**版本前缀固定、只有小尾巴变化**：

- `5.9.0`：应用基础版本，**从今以后静态不动**；
- `0.2.1-rc.2`：跟随 DSH 运行时基线，表达本应用适配的上游版本；
- 末尾的 `x`：本应用自身的迭代号，每次发布只递增这一段。

这样做的价值在于：**看到版本号就能判断它适配的上游基线**，而应用自身迭代次数单独可数，不必从不断增长的补丁号里反推。

### 需要先讲清的一处语义

`5.9.0-0.2.1-rc.2.5` 里 `-` 之后整体是 semver 的 **prerelease**（预发布标识）。按语义化版本规则，预发布版**永远小于**同号正式版，即：

```text
5.9.0-0.2.1-rc.2.5  <  5.9.0
```

本方案不发布 `5.9.0` 正式版，因此比较只发生在两个预发布版本之间——此时末尾迭代号能正确分出先后（`…2.6` > `…2.5`）。这意味着**设备上已装的历史 `5.9.0`（无小尾巴）会被判为更新**，凡是装了它的设备，升级到新方案需要先处理这一点（见「行为约束」）。

## 调研结论

**fnOS 侧的格式约束**（`fnpack` 实测）：

| 候选写法 | `fnpack` 是否接受 | semver 判序 | 与 `5.9.0` 比较 |
| --- | --- | --- | --- |
| `5.9.0-0.2.1-rc.2.5` | 接受，版本原样写入 FPK | 合法预发布版 | **更小** |
| `5.9.0+0.2.1-rc.2.5` | 接受 | 合法，build metadata 不参与比较 | 相等 |
| `5.9.0.5` | 接受 | **非法**（四段） | 取决于平台实现 |

官方文档给出的版本示例包含 `2.1.3-beta` 形态，属于同一类预发布写法，因此格式本身合规。

**本仓库现状**：

- `pnpm-workspace.yaml` 顶层 catalog 已有 `'@deepseek-ai/dsh': 0.2.1-rc.2`，是 DSH 基线的**唯一权威来源**；各插件 `peerDependencies` 用 `catalog:dsh` 引用它，版本命令不应再维护第二份常量。
- 项目版本当前由 `bumpp` 的语义化档位递增，会移动前三段，与本需求冲突。
- 版本命令已支持以**显式版本号**交给 `bumpp`（其 `release` 选项接受具体版本串），因此不必引入新的版本工具。

## 需求目标

1. 项目/FPK 版本号统一为 `<固定基础>-<DSH 基线>.<迭代号>`，当前即 `5.9.0-0.2.1-rc.2.<x>`。
2. `5.9.0` 与 DSH 基线两段由系统维护：基础版本不随发布改变；基线随 catalog 中的 `'@deepseek-ai/dsh'` 自动跟随，不手工维护副本。
3. 每次发布**只递增末尾迭代号**，其余各段保持不变。
4. 版本命令在两种调用下都产出该形态：给档位关键字（`patch`/`minor`/`major`）时按「迭代号 +1」处理；给完整版本串时按其字面值写入。
5. 版本号可被 `fnpack` 打包接受，并原样出现在 FPK 的 `manifest` 与 Git tag 中。

## 行为约束

- **`5.9.0` 不得被任何发布流程改动**。若当前版本串的基础段与之不符，版本命令必须报错，而不是静默改写。
- 基线变化（如 DSH 升到 `0.2.2-rc.1`）时，新版本号的迭代号**在上一次的值上继续递增**，不重置为 0：重置会让新号在排序上退回旧位置，设备会判为降级而拒绝安装。
- 已装 `5.9.0`（无小尾巴）的设备升级到新方案时，由于预发布版排序更小，安装可能被判降级。该情形需要**显式验证并给出处置**（升级、卸载重装或调整方案），不得默认它可用。
- 版本号必须是单行、无空格的纯 ASCII 串，可安全用于目录名、tag 与文件名。
- 不改动插件自身版本流程：插件版本仍为 `<DSH 基线>.<修订号>`，与项目版本是两套独立发布。

## 不在本次范围内

- 插件版本号的形态调整（仍由 `pnpm run version -- plugin <别名>` 维护）。
- 应用市场或应用中心侧的版本比较实现（属平台行为，本仓库不对其做假设，只做实测验证）。
- 历史 FPK 与本方案前版本号的重命名或迁移。

## 既有功能变更关系

- **替换**：项目/FPK 版本由「语义化档位递增」改为「固定前缀 + 迭代号递增」。`pnpm run version -- project patch|minor|major` 的**参数形态保留**，但语义收敛为「迭代号 +1」，不再移动前三段。
- **沿用**：`bumpp` 仍负责版本文件替换、release 提交与本地 tag；插件版本流程完全不变。
- **沿用**：catalog 中的 `'@deepseek-ai/dsh'` 仍是 DSH 基线唯一来源，构建校验 `DSH_VERSION` 与它的一致性维持现状。
