# 插件 UI 规范

本规范约束 `plugins/` 下所有 DSH 插件的客户端 UI 实现。目标是让多个插件在 DSH 宿主中呈现一致的视觉与交互：同一套按钮、浮层、表单和树形选择，在亮色和深色主题下的表现完全统一，且样式只需维护一处。

## 核心原则

1. **优先使用 Semi Design 组件**：插件 UI 优先使用 Semi Design 现成组件，不重复实现按钮、弹窗、下拉、表单等 Semi 已有的能力；确实没有对应组件时才允许自定义实现。
2. **组件统一从共享包导入**：插件不直接依赖 `@douyinfe/semi-ui`。需要 Semi 组件时，一律导入 `@tnnevol/dsh-semi-ui` 导出的 `Dsh*` 组件，由共享包负责转发、封装和按需加载。
3. **样式主题统一维护**：Semi 组件的颜色、边框、圆角、浮层和选中状态映射由 `@tnnevol/dsh-semi-ui` 的主题层统一维护，插件不得自行编写 Semi 主题覆盖样式。
4. **跟随 DSH 主题变量**：所有自定义样式必须使用 DSH 语义变量（`--dsw-*`），不得硬编码颜色值，保证亮色、深色主题自动切换。
5. **一处修改，全部插件生效**：主题与通用组件的调整只在共享包中进行，调整后重建消费插件即可全局生效。

## 适用范围

| 范围 | 是否适用 |
| --- | --- |
| `plugins/*` 的 Client UI（页面、面板、弹窗、设置表单） | 适用 |
| 插件内跨页面复用的 `src/components/`、`src/client/ui/` 组件 | 适用 |
| `packages/dsh-semi-ui` 共享包自身 | 是主题的唯一维护方，见维护职责 |
| 文档站（`docs/`）的 VitePress 页面与 Vue 组件 | 不适用，遵循文档站自身样式体系 |
| Host 侧无 UI 的逻辑代码 | 不适用 |

## 组件选择优先级

新增或修改插件 UI 时，按以下顺序选择实现方式：

| 优先级 | 方式 | 条件 |
| --- | --- | --- |
| 1 | `@tnnevol/dsh-semi-ui` 已导出的 `Dsh*` 组件 | 默认选择，直接使用 |
| 2 | 在 `@tnnevol/dsh-semi-ui` 中新增封装 | Semi Design 存在对应组件但共享包尚未导出；封装并从 `src/index.ts` 导出后使用 |
| 3 | 插件内自定义组件 | Semi Design 没有对应能力；样式必须使用 DSH 语义变量，并在代码评审中说明理由 |

禁止的做法：

- 在插件 `package.json` 中新增 `@douyinfe/semi-ui`、`@douyinfe/semi-icons` 直接依赖，或从这些包导入组件与图标。
- 在插件内编写针对 Semi 类名（`.semi-*`）的主题覆盖 SCSS；同类调整应下沉到共享包。
- 绕过共享包主题层，自行调用 Semi 的主题定制机制。
- 在插件样式中硬编码颜色、圆角或阴影值。

插件常用图标由共享包随组件一并导出（文件、文件夹、关闭、设置、更新日志等），不要为此单独引入 `@douyinfe/semi-icons`。

## 配置项 UI 选择顺序

插件需要暴露配置项时，按以下顺序选择实现方式：

| 优先级 | 方式 | 条件与说明 |
| --- | --- | --- |
| 1 | **DSH 官方配置项 UI**（插件入口导出 `Config` 运行时 schema，如 Schemastery 定义） | 默认选择。官方 settings 表单自动生成、随宿主升级演进、与设置页和插件管理页的接缝天然一致；能用它表达的字段（文本、数字、布尔、枚举、列表等）必须用它 |
| 2 | **Semi UI 自定义配置区块**（`@tnnevol/dsh-semi-ui` 的 `Dsh*` 组件，注册到插件详情页座位） | 仅当官方配置 UI **不满足交互要求**时使用：需要账号卡片、列表管理、文件选择、跨区块布局、实时状态等表单控件表达不了的能力 |

判定规则：

- **先用官方，不满足才上 Semi UI**；「官方能实现但自定义更顺手」不构成绕过的理由。
- 选择 Semi UI 自定义时，必须在插件内用注释说明官方配置 UI 不满足的具体交互要求（缺什么控件、什么流程表达不了），并在代码评审中确认。
- 两者可以并存：能用官方 schema 表达的字段留在 `Config`，交互复杂的部分用自定义区块承载；不要为了统一而把简单字段也搬进自定义 UI。
- 官方 schema 的字段变更（新增、改名、默认值）会直接影响宿主表单与数据持久化，按插件契约处理并同步契约测试。

## 主题接入要求

每个插件 Client 启动时必须安装共享主题，并通过 `ctx.effect` 保证卸载时清理：

```ts
import { installSemiDshTheme } from '@tnnevol/dsh-semi-ui'

export function apply(ctx) {
  ctx.effect(() => installSemiDshTheme(), 'plugin: Semi DSH theme')
}
```

主题层基于 DSH 语义变量工作，不判断浅色或深色。接入后插件内的 `Dsh*` 组件自动获得正确的背景、文字、边框、主按钮反色和浮层表现。

气泡类浮层（Dropdown、Tooltip、Modal 等）的背景必须成对使用官方半透明变量与背景模糊，避免看穿底层内容：

```scss
background: var(--dsw-specific-menu);
backdrop-filter: var(--dsw-menu-backdrop-filter, blur(40px) saturate(150%));
```

毛玻璃的层级约定（测试按此核对，见[测试用例文档规范](./tests-spec.md)的 UI 测试章节）：

- `backdrop-filter` 尽量加在**父元素**：由承载透明背景的容器统一设置模糊，子元素直接继承模糊后的视觉。
- 子元素**禁止重复叠加**：不得同时使用 `backdrop-filter` 与透明背景（两层模糊产生重影与性能损耗）；子元素需要自己的表面时用不透明或半透明纯色变量。
- 一个视觉块只允许一条模糊链路；Safari 18 之前需成对写 `-webkit-backdrop-filter`（共享包主题已处理）。

细节与已知坑见 [DSH Semi UI 共享包](/plugins/dsh-semi-ui)。

## 按钮变体都要覆盖禁用态，且跟随主题

**`theme` 的每个变体在深色下都必须可见。** 共享包主题层（`theme.scss`）只覆盖了
`semi-button-solid` 的禁用态；`theme="light"` 走的是 Semi 自己的
`--semi-color-primary-light-default` 一档，深色下那套值来自浅色主题——近白底 +
浅灰字，落在深色面板上就是一个灰糊糊的圆角块（实测截图：禁用按钮完全读不出文案）。

三条要求：

- **禁用态也要用语义变量**：底色 `color-mix(品牌色 12%, bg-layer-3)`、文字
  `label-tertiary`，亮暗都成立，不写死颜色；
- **`opacity` 必须归 1**：Semi 的禁用样式默认带透明度，再叠一层会让文字更糊；
- **对比度按 AA 核对**：正文 ≥ 4.5、大字 ≥ 3。本项目实测参考：上述取值在深色下
  得到 9.82。

新增任何 `theme` 变体的按钮时，先把它在亮/暗两套主题下各禁用一个看一眼——这是
共享包没覆盖到的地方。

## 空状态：一律用缺省组件，禁止纯文案

**任何「这里没有数据」的位置都必须用缺省组件（`DshEmpty` + 插画），不能用一行
灰字代替。**

包括但不限于：

| 场景 | 反例 | 正例 |
| --- | --- | --- |
| 树形选择器空了 | `emptyContent={t('empty')}` | `emptyContent={<DshEmpty image={…} description={t('empty')} />}` |
| 列表没有条目 | `<p class="body">{t('empty')}</p>` | `<DshEmpty image={…} description={t('empty')} />` |
| 加载失败（渲染阻塞） | 一行红字 | 缺省页，原因放 `description` |

理由：纯文案在一堆有插画的空状态里显得像排版错误或者「加载失败」，用户分不清
「确实没有内容」和「页面坏了」。统一成缺省组件后，形态本身就在传达「这里现在是
空的」。

`Tree`、`List` 这类组件若提供 `emptyContent` 之类的属性，它接受 `ReactNode`——
直接把缺省组件传进去即可。

插画统一用 `FnosEmptyIllustration`（`dsh-fnos-plugin` 内自绘，`stroke` 取
`currentColor` 自动跟随主题）。消费方只需按位置选尺寸：面板内 120、窄条内 96。

## 字号：只允许偶数

**插件样式里禁止出现奇数 `font-size`。** 11 / 13 / 15 / 17… 一律升到相邻偶数
（12 / 14 / 16 / 18）。

两个理由：

- **缩放不糊**：浏览器与非整数 DPR（1.25、1.5）下，偶数号更容易落在整像素上；
  奇数号在小字号区间更容易出现半像素渲染，笔画发虚。
- **相邻档位太难分辨**：13 与 14 的视觉差本就微弱，维护时容易来回改；把档位
  收敛到偶数后，每次调整都是可感知的一档。

与官方对齐时同样遵守这条：官方的账号菜单是 14px、通用 `Menu` 原语是 13px——
**选 14 那一档**，不要为了「一模一样」引入奇数号。

改字号时按「就高」处理（13 → 14），不要往下降（13 → 12）：向下会让本来就偏小的
说明文字更难读。

## 浮层尺寸：外层定尺寸，内层用百分比与 calc

弹框、抽屉这类浮层的宽高**只由最外层容器决定**，内容层跟随。这条不是风格偏好，
而是 Semi 的宽度来源决定的：组件上的 `width={480}` 会写成 `.semi-modal` 的
**内联样式**，内层 `width: 100%` 取的就是这个值——只改内层收不回来，窄屏下整块
弹框会溢出到视口外（实测：标题左侧被切掉）。

```scss
/* 外层：一条 max-width 同时表达「桌面固定宽」与「窄屏不溢出」。 */
.semi-modal:has(> .semi-modal-content.dsh-fnos-xxx-modal) {
  max-width: calc(100vw - 24px);
}

/* 内层：只跟随外层，不自己写死像素。 */
.semi-modal-content.dsh-fnos-xxx-modal {
  width: 100%;
  max-width: min(480px, 100%);
}
```

三条要求：

- **`max-width` 天然约束 `width`**，包括内联样式里写死的那个——不需要
  `!important`。出现 `!important` 才能收住尺寸，说明层级选错了。
- **内层用 `100%` 与 `calc` 表达剩余空间**，不重复写死像素宽高。需要「撑满剩余」
  时用 `calc(100vh - <固定区高度>)` 显式算，比层层 `height: 100%` 传递可靠：
  中间任何一层 `min-height: 0` / `flex: 1 1 auto` 没生效，下面就会回退成内容高度。
- **固定区高度要能被读到**：header 之类的高度值写在一个地方，`calc` 引用同一个数，
  改一处即可。

测试按此核对：窄屏（≤ 767px）与桌面各测一遍，确认浮层左右边界都在视口内、
内层宽度等于外层、没有横向滚动。

## 样式注入顺序：自定义覆盖必须在组件库默认之后

插件样式通过 `exports` 的 JavaScript 入口自行注入（没有 CSS 入口）。注入脚本由
构建期生成，规则见 `tooling/plugin-client-styles`：所有插件样式进同一个容器
`<div data-dsh-plugin-styles>`，容器常驻 `head` 的最后一个元素。

原因有两条，缺一不可：

- **不重复**：插件会被反复加载（热更新、禁用再启用、切 profile）。用固定 id 定位
  自己那份，存在就更新内容。此前无条件 `append`，实测一个页面堆出 4 份内联 Semi、
  合计约 107 万字符。
- **顺序确定**：CSS 同一优先级下后出现的规则胜出。我们的覆盖必须晚于组件库默认
  样式，而插件加载顺序不确定——单靠 `head.append` 等于靠运气。容器固定在 `head`
  末尾，让「自定义样式优先级高于组件库默认」成为可依赖的约定。

由此得到一条写作约定：**同级选择器下，插件样式会压过 Semi 默认样式**，不需要为了
覆盖默认值而抬高特异性或加 `!important`。反过来，若某条覆盖不生效，先检查它是否
真的进了插件样式容器，而不是继续加特异性。

## 环境能力缺失：渲染用缺省页，交互用反馈组件

插件在本地 DSH Web、Desktop 等**没有飞牛 API/SDK** 的环境里也要能正常打开。能力
缺失的承载方式按发生时机分两类，不能混用：

| 时机 | 承载方式 | 例子 |
| --- | --- | --- |
| **渲染时**发现能力不可用 | **缺省页**（`DshEmpty` + 插画） | 授权目录面板在非 fnOS 环境下拿不到数据 |
| **交互中**调用失败 | **反馈组件**（Toast） | 点了「添加目录」「取消授权」后失败 |

两条硬性要求：

- **禁止只甩一句静态文案**。无论是「该能力需要…」这种说明条，还是把错误写进
  state 渲染成一行红字，都缺少交互语义：用户不知道自己能做什么，也分不清是
  环境限制还是操作失败。
- **不要整体屏蔽**。同一面板里各分组的依赖往往不同——本插件的设置面板四个分组，
  只有「授权目录」依赖 fnOS 宿主桥，插件管理 / 运行 / 日志都走插件自己的路由，
  本地完全可用。按环境把整个面板换成缺省页，会把三个本来能用的功能一起关掉。

缺省插画用 `<FnosEmptyIllustration>`（`dsh-fnos-plugin` 内自绘）：只用圆角矩形、
圆与短线，`stroke="currentColor"` 自动跟随主题，不需要维护亮暗两套，也不引入外部
图库的许可与署名问题。

## 本地热更验证

改样式不必每次都构建 FPK 装到 NAS。`start` 的 DSH Web 目标会以仓库根 `.dsh` 为
`DSH_HOME` 启动本地实例（8070），插件产物由 `tsdown --watch` 持续重建；改完 CSS
**刷新页面**即可看到效果。具体命令与注意事项见[测试用例文档规范](./tests-spec.md)
的「DSH Web 本地测试」。

## 共享包维护职责

`@tnnevol/dsh-semi-ui` 是全部插件 Semi 组件与主题的唯一维护入口：

- 组件封装、导出清单和主题映射只在共享包内修改。
- 新增组件必须从 `src/index.ts` 明确导出，并同步更新组件清单。
- 主题调整需同时覆盖亮色与深色表现，不得只修单侧。
- 共享包样式会被内联进消费插件产物，修改主题后必须重建消费插件，不能只构建本包。

## 插件接入检查清单

提交插件 UI 变更前逐项检查：

- [ ] 没有新增 `@douyinfe/semi-ui`、`@douyinfe/semi-icons` 直接依赖或导入。
- [ ] 使用的 Semi 能力均通过 `@tnnevol/dsh-semi-ui` 的 `Dsh*` 组件表达。
- [ ] 新增的通用组件已下沉到共享包并导出，而不是留在单个插件内。
- [ ] Client 启动安装了 `installSemiDshTheme()`，且通过 `ctx.effect` 清理。
- [ ] 配置项 UI 按[配置项 UI 选择顺序](#配置项-ui-选择顺序)选择：能用官方 `Config` schema 表达的字段未搬进自定义 UI；使用 Semi UI 自定义时已注明官方 UI 不满足的具体交互要求。
- [ ] 自定义样式只使用 DSH 语义变量，没有硬编码颜色。
- [ ] 亮色与暗色主题下的文本、阴影、border 与背景对比都成立，主题切换后无残留单侧样式。
- [ ] 相邻元素的 padding/margin 叠加与 BFC 行为符合预期；需要隔离时优先 `display: flow-root`。
- [ ] 毛玻璃 `backdrop-filter` 加在承载透明背景的父元素上，子元素没有重复叠加模糊与透明背景。
- [ ] 没有插件内的 `.semi-*` 主题覆盖样式；主题调整已提交到共享包。
- [ ] 涉及共享包或主题修改时，已重建并验证所有消费插件。

## 例外流程

确需绕过本规范（例如宿主注入的特殊容器、与 Semi 视觉体系无关的画布类 UI）时：

1. 在插件内用注释和评审记录说明原因与影响范围。
2. 自定义样式仍然只使用 DSH 语义变量，保证主题切换不受影响。
3. 一旦共享包补齐对应能力，应及时替换回 `Dsh*` 组件并删除例外实现。
