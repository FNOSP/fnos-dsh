# fnOS

`@tnnevol/dsh-fnos` 为 DSH 提供 fnOS 系统集成，包括访问已授权的 NAS 目录、打开文件和导出会话日志。

## 安装

在 fnOS 上使用 DSH 时，插件随应用安装或升级自动安装。其他 DSH 环境可执行：

```sh
dsh plugin --profile web add @tnnevol/dsh-fnos@8.1.11
```

安装后重启 DSH Web profile。插件版本信息见[插件总览](/plugins/)。

## 授权目录与文件

在「插件」中打开 `fnos` 详情页，选择「添加授权目录」并在 fnOS 窗口中确认。授权后可在工作区选择器中使用目录，也可在对话中选择文件或目录作为上下文。

你可以在插件详情页取消自己授予的目录权限；应用提供的共享目录仅供查看，不能从这里取消。

配置区**始终展开**，没有折叠面板（这一页只有这一块内容），也**不自带外层面板**（无边框、无底色）——宿主给详情页座位的容器本来就只负责排布，插件再套一层带边框的卡片会在页面上形成「框里的框」。目录列表固定 **300px** 上限并自行滚动，目录很多时不会把下面的设置项顶出屏幕。

### 三方插件 proxy

详情页底部的「三方插件 proxy」把三方插件的绝对路径 API 统一接入应用网关，由网关按前缀转发到对应服务。标题右侧的 ⓘ 图标可悬浮或键盘聚焦查看完整说明（三行：是什么 / 怎么写 / 举例子）。

- 每行填一个**以 `/` 开头的绝对路径前缀**，保存后刷新页面生效；前缀填到哪一段为止，看插件 API 的第一段即可——API 是 `/plugin-api/get/me`，就填 `/plugin-api`；
- 文本框最多显示 **8 行**，超出后自行滚动；
- 填写后按 `Ctrl+S`（macOS 为 `⌘S`）可直接保存；
- `/api`、`/plugins` 等网关保留路径不可用，保存时会给出提示。

![fnOS 真机上的授权目录管理：已授权目录、取消授权与第三方插件 proxy 前缀配置](</images/plugins/dsh-fnos/authorized-directories.jpg>)

在 fnOS 中点击对话、工具结果或生成文件里的路径，可交由系统文件管理器打开。会话日志菜单支持下载到当前电脑，或导出到已授权的 NAS 目录。

## 快捷键

插件在内嵌页面里接管了几组本该由浏览器处理的快捷键，避免它们把页面刷新掉或把按键吞掉：

| 快捷键 | 作用 |
| --- | --- |
| `F5`、`Ctrl+R`、`⌘R` | 只刷新 iframe 里的 DSH 页面，不会把 fnOS 宿主页面整页重载 |
| `Ctrl+,`、`⌘,` | 打开 DSH 设置面板；面板已打开时再按一次关闭 |
| `Ctrl+S`、`⌘S` | 在「三方插件 proxy」文本框内保存配置 |

这些接管只在 fnOS 应用的内嵌页面里生效，不影响 fnOS 其它页面的快捷键行为。

## 主题

DSH 主题设为「跟随系统」时会跟随 fnOS 当前主题；如果在 DSH 中明确选择浅色或深色，则以该选择为准。

## 刷新与重启

DSH 页面刷新与上游进程重启收在**会话头部右侧的「…」菜单**里（该菜单同时提供「下载 Session 日志」与「反馈」）。菜单顺序：

| 菜单项 | 作用 |
| --- | --- |
| 刷新 | 重载 iframe 里的 DSH 页面 |
| 下载 Session 日志 | 导出到电脑或 NAS |
| 反馈 | 打开本仓库 |
| 重启 | 重启上游 DSH Web 进程；失败时该行直接显示原因 |

这两项原先是侧栏底部的独立按钮，占掉两个常驻按钮位；都是低频动作，收进菜单后侧栏底部只留「设置」。键盘的 `F5` / `Ctrl+R` / `⌘R` 仍然只刷新 iframe。

## 依赖修复

插件详情页提供「依赖修复」，用于**在应用内安装插件失败**的情况。

最常见的失败是这样的报错：

```text
[ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION] 1 lockfile entries failed verification
```

它表示某个插件版本还没过 pnpm 的发布冷静期，而 profile 里本应放行它的豁免条目仍锚在旧版本上——pnpm 对该字段是「先匹配先赢」，锚在旧版本的条目不会再放行任何东西。

卡片上只有一个「修复依赖」按钮，点它即开始修复。它会**先做一次只读诊断**：

- 若存在失效条目（版本已不匹配安装目标，或旧的多版本合并写法），弹窗确认后执行三步——移除失效条目、重建依赖（`pnpm clean --lockfile` 后重新安装）、装回本应用管理的插件。
- 若依赖状态本来就正常，直接提示「依赖状态正常，无需修复」，**不会**清依赖——避免为了「试试」而白白重建一次。

修复只清理可重建的锁文件与依赖目录；凭据、会话、工作区与配置不受影响，也会保留你为其它插件添加的豁免条目。重建期间应用暂不可用，通常需要一到几分钟。

## 常见问题

### 授权目录列表为空

确认已从 fnOS 应用入口打开 DSH，并在 fnOS 授权窗口中授予目录访问权限。普通浏览器无法提供完整的 fnOS 文件能力。

### 文件无法打开

确认该路径存在，并且当前 fnOS 用户有权访问。出现在授权目录中不代表目录内的每个文件都存在或可访问。

### 主题没有跟随 fnOS 变化

确认 DSH 主题设置为「跟随系统」；手动选择浅色或深色时，DSH 会优先使用该设置。
