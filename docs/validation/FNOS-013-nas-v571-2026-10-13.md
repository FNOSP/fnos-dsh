## 与 FNOS-012 TC-018（真机自愈）的关系

`docs/tests/FNOS-012-...md` 的 `TC-018`（真机自愈耗时与日志可理解性）标注为「未执行」，
本轮升级安装**是该用例需要的场景**，但本轮**没有取得它的判定证据**：

- 自愈的日志标记由 `cmd/install_callback` 的 `heal_profile_release_age_exclusions()`
  输出（`Detected stale minimumReleaseAgeExclude entries ...` / `Web profile dependency
  rebuild completed.`），这些**只写入 NAS 上的 `/var/log/apps/fn-deepseek-harness.log`**；
- 本轮经浏览器（应用中心 UI）驱动安装，**无法读取该文件**；fnOS 的桌面 UI 也未提供
  到达该路径的入口（尝试「日志」与「系统设置」均被应用详情浮层挡住）。

因此 `TC-018` **仍为未执行**，不因本轮安装而改为通过。要点：
本机的 `.dsh/profiles/web/pnpm-workspace.yaml` 里确实存在同形状的失效条目
（`minimumReleaseAgeExclude: ['@tnnevol/dsh-codebuddy@0.1.7-rc.2']`，而清单已是
`0.2.0-rc.2.2`），说明该场景在真实设备上同样可能出现；要判定它，需要 SSH 读取 NAS
日志，或由安装向导把自愈摘要透出到界面。

## 过程中发现的问题

| 问题 | 性质 | 处理 |
| --- | --- | --- |
| FPK 内置打包被守卫拒绝：`unpackable runtime dependency @tnnevol/dsh-plugin-kit@workspace:*` | 阻塞（构建期） | 该包作为运行时依赖无法在 npm 解析且未发布；改为**内联**进产物（`alwaysBundle` + 移到 devDependencies） |
| 内置守卫两处常量过期，`--bundle-dsh-plugins` 在 Midscene 加入前就已失效（清单 4 项 vs 守卫写死 3 项） | 阻塞（构建期） | 改为「必含集合 + 显式允许清单」，版本核对覆盖全部内置插件 |
| Midscene 多选改单选后无法清空 | 回归（界面） | 修正 prop 名（Select 用 `showClear` 而非 `allowClear`）；后按用户要求移除自加按钮，改用 Semi 自带 × |
| 驱动浏览器时会把用户正在看的页面切到前台 | 体验缺陷（测试侧） | `connectTarget` 新增 `activate:false` 静默绑定；经 `agent.page` 代理传参且 tabId 必须为数字 |
