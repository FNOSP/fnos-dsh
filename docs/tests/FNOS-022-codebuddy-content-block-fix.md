## 测试范围与需求分析

被测对象是 `@tnnevol/dsh-codebuddy` 插件的**出站请求改写**与**错误分类**两部分，对应本需求的两项 P0 功能。需求中原有的「参考项目口径对齐」功能已因来源项目停止维护而取消，不在测试范围内。

### 覆盖的功能编号

| 功能 | 覆盖内容 |
| --- | --- |
| FNOS-022-07 | 出站前对系统提示开头的身份说明做单句最小改写；非句首与未命中时逐字不变；改写后语义与模型行为正常 |
| FNOS-022-08 | 内容策略拦截（业务码 11128）独立成码；不重试、不换号；与额度耗尽、请求非法、鉴权失败互不混淆 |

### 关键风险点

| 风险 | 对应的用例方向 |
| --- | --- |
| 改写范围过宽，误伤用户正文 | 非句首出现、用户消息内的同一句必须逐字不变 |
| 改写范围过窄，未覆盖真实请求路径 | `options.system` 与 session 内的系统消息两条路径都必须被改写 |
| 规则被改为子串替换，命中引用文本 | 缺少句末标点、产品名后加字两种形态必须不改写 |
| 重复请求反复改写 | 改写结果必须幂等 |
| 内容拦截被归到可重试集合，放大无效请求 | 可重试集合必须不含该码 |
| 内容拦截被归到 `AUTH`（403 与鉴权失败同码） | 业务码识别必须先于状态码分派 |

### 资料缺口

- ❓ 上游对「句首整句后接内容」的判定已实测（仍拦截），但对「同一句出现在**后续**系统消息开头」未实测；当前实现对每条系统消息各自改写，属防御性覆盖，无实测证据。
- ❓ 上游是否会扩展匹配到其它句子或改为语义判定，无法预期；已登记为计划风险一、风险四与风险五。

## 测试结论

FNOS-022-07 与 FNOS-022-08 **验收通过**：

- 改写可解除上游拦截——真实账号端到端确认（原样发送 400/11128、改写后 200），且 DSH Web 与 DSH Desktop 两个客户端均实测模型正常返回内容；
- 改写范围符合实测边界（句首锚定、整句匹配、非句首不改写），全量用例无回归；
- 内容拦截归入独立错误码 `CONTENT_BLOCKED`，本地桩注入下**只失败一次、不重试、不换号**。

17 条用例全部通过，0 条失败、0 条未执行。

遗留风险：

1. 上游若把匹配扩展到其它句子或改为语义判定，单句改写会失效——失效时表现为一次明确失败（`CONTENT_BLOCKED`），不会静默损坏。
2. 存在与本次修复无关的账号级错误（业务码 11140 / HTTP 403「request illegal」）：排查期间本地有账号出现该状态，需重新登录才能恢复，改写无法解决；已登记在计划风险十。
