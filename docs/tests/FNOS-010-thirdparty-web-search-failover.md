# FNOS-010 测试用例

本文件记录 [FNOS-010](/requirements/FNOS-010-thirdparty-web-search-failover)（三方搜索接入与官方兜底）的测试用例定义、执行结果、发现的 Bug 与最终结论，对应计划 [PLAN-FNOS-010](/plans/PLAN-FNOS-010-thirdparty-web-search-failover)。用例编号、格式与回填规则遵循[测试用例文档规范](/charter/tests-spec)。

## 测试范围与需求分析

被测对象：新增 DSH 插件 `@tnnevol/dsh-failover-search`（目录 `plugins/dsh-failover-search-plugin`），以复合搜索提供方接管会话内网页搜索，按 TinyFish → Tavily → 官方搜索顺序转移，支持同平台多账号均摊、用量快照展示与请求前探测。

覆盖的功能编号：`FNOS-010-01` 至 `FNOS-010-10`。

关键风险点：

- **转移语义**：接缝只支持「配置固定提供方」，多级兜底必须在插件内部实现；顺序、跳过与终止条件写错会让搜索静默失败或产生重复请求。
- **账号均摊与探测**：均摊游标与探测排除共同决定「这次请求打给谁」；探测误判会让可用账号被跳过，或让已触限账号反复被请求。
- **凭据红线**：key 是敏感凭据，且配置表单需要承载它；明文一旦进入会话记录、错误信息或日志即违规。
- **上游契约漂移**：两个三方服务的响应字段与日期格式不是稳定契约（实测已发现 `url` 会返回相对重定向包装）。

资料不足处：`❓` 无。需求与计划中的待核实项已在实现期用真实调用核实，结论记录在下面各用例的结果列与本文件「Bug 记录」中。
