## 测试范围与需求分析

覆盖 [功能列表](/requirements/FNOS-014-dsh-021-rc2-adaptation#功能列表)中 FNOS-014-01 至 FNOS-014-14 全部功能。

本次的核心风险面有三处：

- **加载门禁两条独立路径**：插件能否加载取决于「声明的版本范围是否被运行时满足」与「组合声明注入的服务是否存在」。本次两处都有变化，只验一条会把另一条的问题留到运行时暴露。
- **模型底座跨大版本**：底层模型库从 `0.87.1` 升到 `1.1.0`，Codex Auth 直接构造该库的模型集合与鉴权上下文。单测能覆盖形状，真实账号的登录回流与模型目录刷新必须实测。
- **声明类改动的「一致性」**：本次大部分改动是版本常量与兼容声明，代码行为不变。这类改动的失败模式不是崩溃，而是「本地通过、FPK 装出来不一致」，因此用例必须包含跨文件一致性断言。

❓ 待核实项：新版「凭据缺失的路由不提供模型」在 Codex Auth 未登录态下的具体表现（是否整组隐藏、界面是否给出引导），需要在 DSH Web 与 DSH Desktop 上实测后回填。
