### 迁移与一处构建陷阱

版本方案切换需要把当时的 `5.9.0`（无小尾巴）改成 `5.9.0-0.2.1-rc.2.0`。首次执行版本命令时它输出了 `5.9.0 -> 5.9.1`，即**绕过了新校验**——原因是 `pnpm run version` 调用的是 `tooling/fnos-dsh-cli/lib/index.mjs` 这份**编译产物**，而当时它还是改动前的旧构建。重建 CLI 后校验立即生效（`5.9.0` 被拒绝并给出迁移目标）。该现象与仓库里已记录的「改 `src/` 后必须重建 CLI」是同一类问题，本轮再次踩到，记于此供后续参考。

## 测试结论

**部分通过。** 17 条中 15 条通过，2 条未执行（均为真实设备升级，受环境限制而非产品缺陷）。

**已确定**：版本拆解与组装、迭代号递增、基线来自 catalog、缺迭代号不跳号、基线变化不重置、基础段漂移时报错，均由本地单测覆盖并经变异检验确认断言有牙齿；`fnpack` 接受该版本号，FPK 内 `manifest` 与根 `package.json` 一致。

**未确定**：fnOS 应用中心如何比较这类版本号（同基线不同迭代号能否覆盖安装、已装历史 `5.9.0` 的设备会否被判降级）——平台比较实现未从文档确认，只做实测，缺设备证据前不判通过。
