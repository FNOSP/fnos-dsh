## 测试范围与需求分析

被测对象是 `@tnnevol/dsh-codebuddy` 插件对**账号级受限**（HTTP 403 + 业务码 11140 + 文案 `request illegal`）的识别与故障转移，以及配套的可见提示、受限账号排除与全部受限时的报错。

### 关键风险点

| 风险 | 用例方向 |
| --- | --- |
| 11140 同时承载模型级限流文案，误判成账号受限会导致无谓换号 | 两种文案分别断言 |
| 受限被误判为鉴权失败（`AUTH`）会让上层丢弃内存凭据 | 断言不返回 `AUTH`，且 401 仍为 `AUTH` |
| 受限账号被选为切换目标，切过去再失败一次 | 主动/被动两条决策路径都断言排除 |
| 受限触发被「自动切换」偏好拦住，账号受限时插件仍不可用 | 偏好关闭下仍应切换 |
| 切换提示不可见，用户不知道发生了什么 | 真实会话中断言提示文本出现 |
| 受限状态写入凭据文件 | 断言落盘结构未变化（受限只在进程内） |

## 测试环境

被测插件不依赖 fnOS 专属能力，**不要求真实 NAS 验收**。

## 测试结论

FNOS-023 的 4 项功能**验收通过**：受限账号能触发自动切换（含偏好关闭的情况）、提示按原因说明且界面可见、受限账号在恢复前不再被选中、全部受限时如实报错；内容拦截与鉴权失败语义未受影响。

遗留项：

1. **DSH Desktop 未单独走查**——本次改动全部在宿主侧，Web 与 Desktop 共用同一适配器与决策逻辑；按兼容基线仍建议补一次 Desktop 走查，登记为后续。
2. 受限标记只在进程内，宿主重启后该账号会再失败一次（设计取舍，见计划风险三）。
