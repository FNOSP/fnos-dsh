## 计划目标

按 FNOS-026 的功能编号实现一个不依赖 fnOS 宿主桥接的 DSH 插件 `@tnnevol/dsh-opencode`：

- **FNOS-026-01**：宿主侧的 Console 登录（设备码与 API Key）与凭据持久化；已登录时账号卡片隐藏 API Key 登录入口；
- **FNOS-026-02**：把 OpenCode Zen（按量）与 OpenCode Go（套餐）两组活 roster、公开目录与账号级覆盖合并注册成 DSH 模型供应商 `OpenCode`（路由 `dsh-opencode`）；每个模型的显示名追加 `· zen` / `· go` 后缀（同名模型因此可区分），内部 id 用 `zen:` / `go:` 前缀保证唯一；
- **FNOS-026-03、FNOS-026-04**：按上游目录把协议族、容量、推理、工具、图片输入、文本与免费标记投影到合并列表中的模型，并保证对话可用；
- **FNOS-026-05、FNOS-026-06**：Go 套餐额度卡片与对话输入区用量胶囊；`zen` 后缀模型不显示套餐额度，胶囊 auto 策略只对 `go` 后缀模型挂出；
- **FNOS-026-07、FNOS-026-08**：模型目录管理（固定高度、搜索、计数与能力图标、按 `plan:id` 逐模型显隐）、登录态与偏好持久化；
- **FNOS-026-09**：文档站说明页与菜单；市场源列表登记随 npm 发布执行。

技术边界：只新增插件与本仓库文档，不改 DSH 核心、其它插件与既有需求文档。FNOS-026-09 本轮完成页面与菜单；源列表登记、市场索引重生成与应用发布清单登记依赖 npm 发布，列为待执行任务。

## 当前实现与目标设计

| 领域 | 当前实现 | 目标实现 | 迁移影响 |
| --- | --- | --- | --- |
| 供应商路由 | 本插件曾注册两组路由 `dsh-opencode`（`OpenCode`）与 `dsh-opencode-go`（`OpenCode Go`），同名模型在两个分组各出现一次 | 只注册一个路由 `dsh-opencode`（显示名 `OpenCode`）；Zen 与 Go 两类来源在同一个供应商下列表 | 选择器只出现一个 `OpenCode` 分组；退出登录时该分组整体撤销；与手工配置 `opencode` / `opencode-go` 并存 |

| 插件详情页 | 目录卡片固定高度、内部滚动，工具栏含「全部 / Go / Zen」分组筛选、plan 标签与计数 | 目录卡片固定高度、内部滚动；工具栏只保留搜索与计数（含已隐藏数）；每行显示后缀、能力图标与逐模型显隐开关 | 移除分组筛选与 plan 标签；显隐偏好改按 `plan:id` 保存 |
| 分发与文档 | 仓库中没有该插件的页面、菜单条目与市场条目 | 说明页 + 插件总览行 + 菜单条目；发布后登记市场源列表、重生成索引并登记应用发布清单 | 文档站与市场可见性随发布推进 |

## 架构与数据流

插件分宿主与浏览器两侧：宿主侧负责凭据、合并后的模型目录、Go 套餐额度与单一供应商适配；浏览器侧只渲染详情页卡片与输入区胶囊，两者通过插件同源 Web 路由通信。所有上游请求由宿主发出，浏览器不接触令牌。

```mermaid

  subgraph Client["DSH 浏览器半侧"]
    Page["插件详情页：账号 / 额度 / 合并目录（搜索、计数、能力图标、显隐）"]
    Pill["对话输入区用量胶囊（auto 仅 · go 模型）"]
  end
  subgraph Host["DSH 宿主半侧（@tnnevol/dsh-opencode）"]
    Routes["同源 Web 路由"]
    Auth["账号服务与凭据存储"]
    Directory["模型目录服务（Zen + Go 合并，plan:id）"]
    Usage["Go 套餐额度服务"]
    Prefs["偏好存储"]
    Adapter["模型供应商适配器（dsh-opencode；请求前剥离 plan 前缀）"]
  end
  subgraph Upstream["OpenCode"]
    Console["OpenCode Console（账号、覆盖配置、额度）"]
    ZenRoster["OpenCode Zen 活 roster"]

  Routes --> Auth
  Routes --> Directory
  Routes --> Usage
  Routes --> Prefs
  Auth --> Console

  Directory --> GoRoster
  Directory --> Public
  Usage --> Console
  Adapter --> Directory
  Adapter --> Gateway
```

目录与额度的刷新都走「先看缓存是否过期，再决定是否打上游」的路径；两类来源分别回退、合并成一份快照，Console 配置读取失败只影响账号覆盖，不影响模型全集：

```mermaid

  participant Service as 目录与额度服务
  participant Console as OpenCode Console
  participant Roster as Zen / Go 活 roster
  participant Public as 公开目录

    Service->>Public: 读取 api.json 的 opencode / opencode-go 段
    alt Console 不可用
      Console-->>Service: 失败原因
      Note over Service: 仍用两组 roster 与公开目录构建合并目录，只记录未应用账号覆盖
    end
    alt 某组 roster 不可用
      Roster-->>Service: 失败原因
      Service->>Public: 回退该来源公开目录段与内置目录

    end
    Note over Service: 合并条目：显示名加 · zen / · go，稳定键为 plan:id
  end
  Service-->>Routes: 合并快照、获取时间与降级说明
  Routes-->>UI: 账号状态、模型目录、Go 额度
```

## 交互和行为设计

### 插件详情页

入口为「插件管理 → `OpenCode` → 详情页」。页面由上到下依次是账号卡片、套餐额度卡片、模型目录卡片与设置区；所有操作只改插件自己的数据。

| 区块 | 状态 | 用户可见内容 | 可用操作 |
| --- | --- | --- | --- |
| 账号卡片 | 未登录 | 两种登录方式说明，「设备码登录」与「用 API Key 登录」入口 | 发起登录 |
| 账号卡片 | 授权中 | 一次性代码、复制按钮、验证地址、剩余有效期 | 取消登录 |
| 账号卡片 | 已登录 | 账号、组织、登录方式与登录时间；只显示退出登录，不显示 API Key 登录入口 | 退出登录 |
| 账号卡片 | 错误 | 失败原因与可执行的处置 | 重试 |
| 额度卡片 | 有数据 | OpenCode Go 的 5 小时、每周、每月三个窗口的已用百分比、重置倒计时、获取时间 | 刷新 |
| 额度卡片 | 失败或未订阅 | 失败原因与最近一次获取时间，或未订阅 Go 的说明；两者都不显示 0% | 刷新 |
| 目录卡片 | 有数据 | 固定高度的滚动列表；固定的搜索框与计数；每行包含名称与 `· zen` / `· go` 后缀、标识、能力图标、容量与逐模型显隐开关 | 搜索、隐藏/恢复、刷新 |
| 目录卡片 | 空或失败 | 说明与重试入口；失败时保留上一份列表 | 刷新 |
| 设置区 | 始终 | 用量胶囊策略、自动刷新间隔 | 修改并保存 |

### 模型目录卡片

目录卡片自身固定高度，只有模型列表区内部滚动；卡片头部与工具栏（搜索框、计数、刷新）不随列表滚动，长目录不会把整页撑高。

| 列表项 | 内容 |
| --- | --- |
| 来源与名称 | 模型名后追加 `· zen`（按量）或 `· go`（套餐），与内部键 `zen:<id>` / `go:<id>` 一一对应 |
| 标识与容量 | 原始模型 id、上下文窗口与最大输出 |
| 能力 | 「推理 / 工具 / 图片 / 文本 / 免费」五个图标；悬浮时显示气泡，逐项标记勾选或未勾选 |
| 显隐 | 逐模型开关；偏好按 `plan:id` 保存，同名 zen/go 条目可分别隐藏 |

- 目录卡片不再提供「全部 / Go / Zen」分组筛选；一个列表内同时展示两类来源，来源由模型名后缀表达。
- 搜索覆盖名称、id、家族、描述与协议族；计数显示当前搜索结果数，已隐藏数量另行标注。
- 目录来源、获取时间与刷新入口保留在卡片头部；目录刷新失败时列表保留上一份快照并显示原因。
- 合并列表内同名条目必须在显示后缀与隐藏键上可区分，不允许出现两个完全相同的行。

### 用量胶囊

胶囊位于对话输入区右侧，与其它状态控件同行，不遮挡输入框。三种策略的切换关系如下：

```mermaid
stateDiagram-v2
  [*] --> auto
  auto --> always: 用户选择常驻
  always --> auto: 用户改回自动
  auto --> off: 用户关闭
  off --> auto: 用户改回自动
  always --> off: 用户关闭
  off --> always: 用户选择常驻
  note right of auto: 仅在选中带 go 后缀的模型时显示
  note right of off: 隐藏并停止自动刷新
```

- `auto`：默认值。只在当前选中的模型属于 `OpenCode` 且带 `go` 后缀（内部键以 `go:` 开头）时显示；带 `zen` 后缀的模型与其它供应商模型不显示，也不触发套餐额度请求。
- `always`：只要插件已登录就常驻显示，与当前选中的供应方无关；没有 Go 套餐数据时显示未知或未订阅，不补 0%。
- `off`：完全不显示，并停止额度自动刷新；详情页额度卡片不受影响，仍可手动刷新。

策略变化在宿主侧持久化，下一次进入会话或下一次对话即按新策略显示，无需重启 DSH。

### 文案与命名

- 供应商名称固定为 `OpenCode`，路由 id 固定为 `dsh-opencode`。
- 两类来源名称固定为 `OpenCode Zen`（按量）与 `OpenCode Go`（套餐）；合并列表中的显示名后缀固定为 `· zen` / `· go`，内部模型键固定为 `zen:<id>` / `go:<id>`。
- 需要说明计费或约束时写「带 `go` 后缀的模型」「`OpenCode Zen`（按量）」，不写成「Zen 套餐」「Go 按量」，也不把后缀解释成独立供应商。
- 目录卡片不显示 plan 标签；来源统一由模型名后缀表达，不再使用「按量 / Go 标签」的说法。
- 三个额度窗口统一称「5 小时」「每周」「每月」，不混用「滚动窗口」「周额度」等别名。
- 「目录来源」按来源说明模型集合来自活 roster、公开目录还是内置目录；账号配置不可读时另附「未应用账号覆盖」说明，不写成「降级」以免被理解为功能受损。
- 上游限制使用错误码与原文短语（`Insufficient account funds`、`FreeTierError`），不翻译成模糊的「额度问题」或「权限问题」。

## 数据、权限和错误处理

### 持久化

| 数据 | 位置 | 权限 | 读取与恢复策略 |
| --- | --- | --- | --- |
| 账号凭据（设备码令牌或 API Key、账号与组织信息） | `$DSH_HOME/.dsh-opencode-auth.json` | 文件 `0600`，目录 `0700` | 只由插件宿主读写，同一凭据同时服务合并后的一个供应商；解析失败或格式版本不符时按未登录处理并给出可诊断错误，不覆盖原文件 |
| 插件偏好（胶囊策略、刷新间隔、隐藏模型） | `$DSH_HOME/.dsh-opencode-preferences.json` | 文件 `0600` | 隐藏模型按 `plan:id` 保存；缺失或损坏时回落到默认值；越界值夹到合法区间 |
| 目录与额度快照 | 进程内存 | — | 合并目录与两类来源快照分别缓存；进程重启后重建，不落盘，避免把过期数据当成事实 |

### 权限

- 不新增 DSH 权限项，也不申请 fnOS 宿主权限；插件只做宿主侧文件读写与对 `opencode.ai` 的出站请求。
- 凭据文件权限被放宽或属主不可读时，按共享包的既有判定给出可诊断错误，不静默忽略。

### 错误处理

| 场景 | 用户可见 | 恢复动作 |
| --- | --- | --- |
| 未登录 | 账号卡片显示登录方式说明 | 发起登录 |
| 设备码过期或取消 | 回到未登录并说明原因 | 重新发起 |
| 令牌失效且续期失败 | 账号卡片回到未登录并提示重新登录 | 重新登录 |
| 账号覆盖配置不可读 | 目录卡片按来源说明当前目录来源与未应用账号覆盖的原因 | 刷新或稍后重试 |
| 某来源活 roster 不可读 | 该来源回退公开目录与内置目录；目录卡片显示来源与失败原因 | 刷新 |
| 合并目录来源都不可读 | 目录卡片显示失败原因，保留上一份可用目录 | 刷新 |
| 额度不可读 | 额度卡片显示未知与失败原因，不显示 0% | 刷新 |
| 账号未订阅 OpenCode Go | 额度卡片显示未订阅说明，不显示 0%；模型目录仍可使用 | 在 Console 订阅后刷新 |
| Zen 余额不足（402） | 会话显示上游原文 `Insufficient account funds` 与可读说明；不自动重试 | 在 Console 充值后重试 |
| Zen 免费模型受限（403） | 会话显示 `FreeTierError` 与「仅可在 OpenCode 客户端使用」的说明；DSH 可能把该上游 403 归类为 AUTH 错误，按上游限制说明；不绕过上游限制 | 改用付费 Zen 模型或 Go 模型 |
| 模型地区限制（403） | 会话显示上游原文（`RegionError` / `unsupported_country_region_territory`）与说明；不自动换模型、不重试 | 改用当前地区可用的同协议模型 |
| Google 工作空间隐私设置（400） | 会话显示上游原文与「需在工作空间 Privacy 设置允许会用于训练的付费端点」说明；不绕过 | 在 Console 允许后重试 |
| `opencode` / `opencode-go` 手工配置 | 不冲突；插件路由 `dsh-opencode` 与手工配置并存 | 无需处置 |
| 用户手工配置了同名 `dsh-opencode` | 详情页说明冲突来源与处置方式；插件不注册、不覆盖用户配置 | 用户移除同名配置后重试 |
| 网络不可直达 `opencode.ai` | 各卡片显示连接失败 | 检查网络后重试 |

| OpenCode Zen 免费模型只允许 OpenCode 客户端使用 | 调用失败（403 `FreeTierError`，DSH 可能显示为 AUTH），用户误以为是插件缺陷 | 目录仍按 roster 展示；会话按上游限制说明；说明页与测试文档登记为已知上游限制 |
| 部分模型受地区限制 | 调用失败（403），用户误以为是插件缺陷 | 目录仍按 roster 展示；会话显示上游原文；说明页与测试文档登记为已知上游限制 |
| Gemini 需要工作空间隐私设置 | 调用失败（400），用户误以为是协议未适配 | 会话显示上游原文与设置入口说明；测试文档登记为阻塞项 |
| 两类来源的 roster 模型数量与名称持续变化 | 文档中的「85 / 37」「122」与真实目录漂移 | 文档只写约数与实测日期并注明以实时目录为准；目录每次刷新按 roster 重建，不依赖内置快照 |
| Console 覆盖配置或额度响应字段漂移 | 增补/停用、能力覆盖或额度解析失败 | 模型全集不受影响（仍来自 roster/公开目录）；账号覆盖与额度显示未知并给出来源说明；解析层以夹具固定已知形态，失败时降级而非抛错到界面 |
| 公开目录体积较大 | 频繁刷新带来带宽与延迟开销 | 公开目录按小时级节流，roster 与账号配置按分钟级；只有强制刷新才立即全量拉取 |
| 运行环境无法直连 `opencode.ai` | 登录、目录与对话全部不可用 | 明确提示连接失败并停止重试；不内置代理，不静默回退到其它供应商 |
| 上游文档把 DSH 列为会话头支持不完整的客户端，部分模型路径可能缺稳定会话标识 | 可能影响网关的路由与缓存优化，不阻断调用 | 登记为观察项，不在本需求范围；以真实账号用例观察是否出现可感知影响 |
| 用户把「已用百分比」误解为金额或剩余额度 | 误判可用性 | 卡片与胶囊只展示百分比与重置时间，窗口名称与 Console 保持一致，不换算金额 |
| 固定高度滚动区域在小屏或键盘操作下可用性下降 | 目录较长时用户难以定位或滚动 | 用例核对滚动容器的键盘可达性与小屏布局；不满足时补焦点样式与滚动提示；搜索与计数保持固定 |
| npm 上目标版本已被占用 | 发布失败 | 发布前核对目标版本，必要时先推进版本 |

### 决策

| 决策 | 选择 | 否决方案 | 原因 |
| --- | --- | --- | --- |
| 供应商路由名 | 唯一路由 `dsh-opencode`（显示名 `OpenCode`） | 沿用 `opencode` / `opencode-go` | `opencode` / `opencode-go` 是 pi-ai 内置目录路由，用户可能在 `llm-pi-ai` 设置里手工声明；实测同名会与本插件注册冲突，导致登录后模型不出现。`dsh-` 前缀避开用户配置 |
| 供应商分组 | 合并为一个 `OpenCode` 供应商，列表内用显示名后缀 `· zen` / `· go` 区分来源 | 按来源拆成两组供应商（上一轮实现） | 两类来源共用同一账号与同一网关，同名模型在两组重复出现；合并后选择器只出现一个分组，来源仍由后缀可读，隐藏与胶囊判断用 `plan:id` / `go:` 前缀即可表达，不需要第二层供应商分组 |
| 合并列表内的模型标识 | 内部 id 用 `zen:` / `go:` 前缀保证唯一，显示名追加后缀；请求前剥离前缀 | 只加显示名后缀、不改 id；或不加前缀，靠顺序区分 | 只改显示名无法让合并列表内的同名模型 id 唯一，选择、隐藏与请求都会指向同一 id；加前缀并在插件请求入口剥离，可同时保证唯一性与网关兼容 |
| 目录来源优先级 | 每类来源「活 roster → 公开目录对应段 → 内置目录或上一份快照」；Console 配置只做增补、停用、能力/容量覆盖与路由头 | 把 Console 配置当启用全集；或只用静态内置目录 | Console `models` 可为空，把它当全集会得到空目录；活 roster 才是模型全集，Console 只承载账号级覆盖与路由头 |
| 目录缓存策略 | 分层 TTL、两类来源共享一次刷新并各自保留来源快照、强制刷新忽略节流 | 每次打开都全量拉取 | 公开目录体积大，分层可兼顾新鲜度与开销；单来源失败不拖累另一来源 |
| 凭据存放位置 | 插件自有的 `0600` 宿主文件，一份凭据服务合并后的供应商 | 写入 profile 配置或复用环境变量 | 凭据形态（访问令牌、续期令牌与账号元信息）超出 DSH 通用凭据字段；环境变量对普通用户不可管理 |
| 目录卡片布局 | 固定高度、列表内部滚动，搜索与计数固定在工具栏；不提供按来源分组筛选 | 让卡片随模型数量撑高整页；或保留分组筛选 | 合并后列表上百个模型；若随内容撑高会把详情页其它卡片推到很远。来源已由每行后缀表达，再加一层筛选只增加操作步骤 |
| 能力展示方式 | 五个能力图标 + 悬浮气泡勾选，容量以文本显示 | 每个能力一个标签堆在行内 | 标签堆叠在合并后上百行时噪声大；图标加气泡在保持可扫读的同时提供细节 |
| 套餐额度适用范围 | 只对 OpenCode Go 生效；`zen` 后缀模型不占用套餐额度 | 两类来源共用同一额度面板 | Zen 按量不占用套餐额度，混用会误导用户判断可用性 |
| 界面承载方式 | 插件详情页自定义区块 | 设置弹框的官方配置表单 | 账号、额度与目录都是交互型区块，官方配置 schema 表达不了（按插件 UI 规范第 2 档） |
| 图片生成模型 | 不纳入适配 | 作为不可选条目展示 | DSH 对话需要文本输入协议；混入会让用户选中后无法对话 |
| 市场索引维护 | 只加源列表，发布后重生成 | 手工改写生成的索引文件 | 索引由官方生成器从 npm 产物读取，手改会与源列表漂移 |

## 测试、打包、发布和回滚

- **包级验证**：插件类型检查、单测与构建；SDD 文档检查与文档站构建。测试用例设计见[测试用例文档 FNOS-026](/tests/FNOS-026-dsh-opencode-plugin)，本页不展开用例表。
- **DSH Web**：`pnpm run start -- --web`（`DSH_HOME` 指向仓库 `.dsh`），用启动日志里带 token 的地址访问；覆盖单一 `OpenCode` 供应商与 `· zen` / `· go` 后缀、合并目录、登录、对话、Go 额度与胶囊，并执行「已手工配置 `opencode`」的路由冲突回归。
- **DSH Desktop**：使用上游检出的开发态 Desktop（`fork-pj/deepseek-harness`），通过渲染进程调试端口取证；重点核对系统浏览器打开验证页、目录卡片固定高度与滚动、能力气泡、合并列表与输入区胶囊位置。
- **文档站**：`pnpm run build -- --docs`（或 `pnpm exec vitepress build docs`）与 `git diff --check`；逐项核对新增菜单与页面链接目标存在。
- **打包与发布**：按仓库版本流程更新版本（功能提交与版本提交分开），随后发布插件；发布后重新生成市场索引，并登记到应用发布清单。
- **回滚**：停用或卸载插件即可撤销 `OpenCode` 供应商注册，模型选择器回到手工配置方式；说明页、插件总览行、菜单条目与市场源列表按提交回退。插件自有的凭据与偏好文件只有用户明确要求时才删除。
- **禁止删除**：用户会话历史、其它供应商的凭据与配置；本插件不持久化目录与额度，无需清理这两类数据。
