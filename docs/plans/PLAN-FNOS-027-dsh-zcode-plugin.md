## 计划目标

按 FNOS-027 的功能编号实现一个不依赖 fnOS 宿主桥接的 DSH 插件 `@tnnevol/dsh-zcode`：

- **FNOS-027-01**：宿主侧的 ZCode 账号 OAuth 设备授权登录（BigModel 国内 / Z.ai 海外两个家族）、单飞轮询与凭据持久化；**不提供 API Key 登录**；
- **FNOS-027-02**：把账号权益（额度条目的 `capabilities`）作为模型清单真源，注册 DSH 模型供应商 `ZCode`（路由 `dsh-zcode`），并以稳定设备标识满足上游额度接口的必填头要求；
- **FNOS-027-03**：按上游客户端配置把上下文窗口、最大输出、图片输入与思考等级投影到模型，缺失时使用保守默认值；
- **FNOS-027-04**：Start Plan 回合改由托管的官方 agent 运行时（`zcode app-server`）执行——客户端身份与请求签名由官方二进制自己构造，插件只做协议、账号注入与事件转写；插件自有的 HTTP 通道只服务 `ultra` 端点。业务码（`3001` / `3006` / `3007` / `1113` / 兜底 `3012`）映射为可读中文诊断；
- **FNOS-027-05**：按「模型 × 周期」展示额度窗口与套餐，保留上游粒度，缺失显示未知；
- **FNOS-027-06、FNOS-027-07**：插件详情页（账号、额度、目录、设置）、对话输入区用量胶囊与登录态/偏好持久化；
- **FNOS-027-08**：文档站说明页与菜单；市场源列表登记随 npm 发布执行。

技术边界：只新增插件与本仓库文档，不改 DSH 核心、其它插件与既有需求文档。FNOS-027-08 本轮完成页面与菜单；源列表登记、市场索引重生成与应用发布清单登记依赖 npm 发布，列为待执行任务。

**本轮的关键约束**：插件自己构造的 Start Plan HTTP 请求会被上游按来源拦截（HTTP 405 与业务码 `3012`），因此执行通道改为托管官方 agent 运行时；该运行时由官方发行包提供，插件不复刻请求签名、不伪造客户端身份、不内置代理或转发。通道有三个静默失败前提（数据目录可写、revision 精确匹配、提交前垫时），并且工具由 ZCode agent 原生执行、一个会话同时只允许一个在途回合。DSH Web 已完成三轮端到端对话，DSH Desktop 待走查。

## 当前实现与目标设计

| 领域 | 当前实现 | 目标实现 | 迁移影响 |
| --- | --- | --- | --- |
| 供应商路由 | 仓库内没有 ZCode 供应商；用户只能用内置 `llm-pi-ai` 手工声明 OpenAI 兼容路由，或直接在 ZCode 客户端里用 | 只注册一个路由 `dsh-zcode`（显示名 `ZCode`），目录由账号权益驱动 | 选择器新增一个 `ZCode` 分组；退出登录时该分组整体撤销；与手工配置的 `zcode` / `zhipu` 并存 |
| 模型清单来源 | 手工配置必须逐条维护，且无法反映账号权益变化 | 以 `billing/balance` 的 `capabilities` 为真源；`client/configs` 只补全能力；两者都不可读时回退内置清单并标记未经账号确认 | 权益变化后刷新即生效，不需要改配置或升级插件；降级时界面说明来源 |
| 账号登录 | 无 | OAuth 设备授权：客户端生成 pollToken → init 取授权地址 → 单飞轮询取令牌；两个家族只差授权页域名 | 账号卡片提供家族选择；不提供 Key 入口 |
| 模型能力投影 | 手工配置只能给一个「兼容」壳子 | 上下文窗口、最大输出、图片输入、思考等级来自 `client/configs`；思考等级按 `off` / `minimal` / `low` → `low`、`medium` / `high` → `high`、`xhigh` / `max` → `max` 归并为上游三档 | 容量与能力随账号配置变化；缺失时用保守默认值并说明 |
| 额度口径 | 无 | 按「模型 × 周期」展示，日额度与一次性活动额度分列 | 界面不出现单一总百分比；不做金额换算 |
| 执行通道（Start Plan） | 插件在 Node 侧构造 Anthropic Messages 请求并复现客户端身份头；该请求被上游按来源拦截（HTTP 405 + `3012`） | 托管官方 `zcode app-server` 子进程：官方二进制自行构造并签名请求，插件只做 stdio 协议、账号注入与事件转写 | 不再需要复刻签名；新增对客户端发行包的运行时依赖；回合由 agent 侧执行 |
| 执行通道（Ultra） | 无 | 保留 pi-ai 的 HTTP 通道，端点为 `ultra/anthropic`，用家族 MaaS 令牌按量计费 | 与 Start Plan 共用同一条 `dsh-zcode` 路由，按端点策略分流 |
| 通道数据与凭据 | 无 | 插件在 DSH home 下自建可写数据目录 `zcode-bridge`；provider 配置使用发行包自带的 `zcode-builtin.json`；凭据按客户端同款 AES-256-GCM 写入 | 不读写用户 `~/.zcode`，不依赖桌面端登录态；目录在每次启动时对账 |
| 模型标识 | 目录 id 来自额度接口（全小写，如 `glm-5.3-flash`） | 桥接通道提交前映射为 agent registry 的规范书写（如 `GLM-5.3-Flash`），无对应项时原样透传 | `session/setModel` 不再因大小写与分隔符差异被拒 |
| 分发与文档 | 仓库中没有该插件的页面、菜单条目与市场条目 | 说明页 + 插件总览行 + 菜单条目 + 三份 SDD 文档；发布后登记市场源列表 | 文档站与市场可见性随发布推进 |

供应商注册只有「未登录 / 已登录」两个状态，变化点在目录的来源与可信度，而不是供应商分组：

```mermaid
stateDiagram-v2
  [*] --> 未登录
  未登录 --> 已登录: 设备授权完成
  已登录 --> 权益目录: 额度接口可读
  已登录 --> 兜底目录: 额度接口不可读
  权益目录 --> 兜底目录: 接口失败且无上一份快照
  兜底目录 --> 权益目录: 刷新成功
  权益目录 --> 未登录: 退出登录
  兜底目录 --> 未登录: 退出登录
```

登录与首轮目录的时序：宿主在插件挂载时先同步给出一份内置清单，保证 headless 首轮对话不会落到空 provider 上；真实目录随后台刷新替换。

```mermaid
sequenceDiagram
  participant Host as 插件宿主
  participant LLM as DSH 模型层
  participant Selector as 模型选择器
  participant Auth as 登录服务
  participant ZCode as ZCode 控制面
  Host->>LLM: registerAdapter('dsh-zcode')
  Host->>Host: 先用内置清单建立同步快照
  LLM-->>Selector: 出现 ZCode 分组（清单未经账号确认）
  Host->>Auth: 读取凭据并异步刷新目录
  Auth->>ZCode: 读取额度（携带账号 JWT 与稳定设备标识）
  ZCode-->>Auth: 套餐与按模型额度
  Auth-->>Host: 权益条目
  Host->>ZCode: 读取客户端配置补全能力
  Host->>LLM: 用新目录重建 profile
  LLM-->>Selector: 清单与服务账号权益一致
```

执行通道在满足「客户端 CLI 可定位、内置 provider 配置可读、数据目录可写、账号已登录」后才就绪；任一前提缺失都给出可读原因，不静默降级成 HTTP 直连：

```mermaid
stateDiagram-v2
  [*] --> 不可用
  不可用 --> 就绪: 客户端与配置可定位 + 数据目录可写 + 账号已登录
  就绪 --> 执行中: 提交回合
  执行中 --> 就绪: 正常结束
  执行中 --> 失败: 回合失败 / 超时 / 子进程退出 / 中止
  失败 --> 就绪: 下一轮重建会话
  就绪 --> 不可用: 退出登录或凭据失效
  不可用 --> [*]
```

一轮对话的协议与数据流如下。`变更点：` 相比原 HTTP 直连方案，模型请求的发送者从插件变成了官方 agent 运行时：

```mermaid
sequenceDiagram
  participant DSH as DSH 会话
  participant Host as 插件宿主（桥接适配器）
  participant App as zcode app-server 子进程
  participant ZCode as Start Plan 网关
  DSH->>Host: stream(options)
  Host->>Host: 准备数据目录、写凭据与 provider 配置、灌入账号
  Host->>App: session/create → subscribe → setMode → setModel
  App->>Host: session/requestRuntimePreferences
  Host-->>App: 固定运行期偏好
  Note over Host,App: 变更点：模型请求由 agent 自行构造并签名
  Host->>App: session/send（首轮压平的历史 + 本轮正文 + 图片路径）
  App->>Host: interaction/requestProviderRuntimeHeaders
  Host-->>App: 账号凭据 + 客户端身份头
  App->>ZCode: Anthropic Messages 请求（agent 侧发起）
  ZCode-->>App: SSE 流
  App-->>Host: session/event（model.streaming / turn.completed / turn.failed）
  Host-->>DSH: 文本、思考与 usage chunk
```

通道的回合失败、超时、中止与子进程退出都会在 `finally` 中补发 `session/stop`，避免回合锁残留影响下一轮。

## 架构与数据流

插件分宿主与浏览器两侧：宿主侧负责凭据、账号权益目录、额度、桥接通道与唯一供应商适配；浏览器侧只渲染详情页卡片与输入区胶囊，两者通过插件同源 Web 路由通信。登录、目录与额度请求由宿主发出，**Start Plan 的模型请求由托管的 agent 子进程发出**；浏览器不接触令牌。

```mermaid

    Page["插件详情页：账号 / 额度 / 目录（搜索、隐藏、刷新）"]

  end
  subgraph Host["DSH 宿主半侧（@tnnevol/dsh-zcode）"]
    Routes["同源 Web 路由"]
    Auth["登录服务与凭据存储"]
```

桥接通道的数据目录由插件在 DSH home 下自建并每次启动对账；三份文件（凭据、`setting.json`、空的个人 provider 规则）缺一不可，否则客户端会退到 `0.0.0-dev` 目录、注入的 revision 与它对不上。

目录与额度的刷新都走「先看缓存是否过期，再决定是否打上游」的路径；额度接口失败只降级清单来源，不清空已经可用的目录：

```mermaid

  participant UI as 详情页 / 用量胶囊
  participant Routes as 插件 Web 路由
  participant Service as 目录与额度服务
  participant ZCode as ZCode 控制面
  UI->>Routes: 读取账号状态、目录与额度
  Routes->>Service: 判断缓存是否过期
  alt 已过期或用户强制刷新
    Service->>ZCode: 读取 Start Plan 额度（账号 JWT + 稳定设备标识）
    alt 额度不可读
      ZCode-->>Service: 失败原因
      Note over Service: 回退内置清单并保留上一份目录，标记清单未经账号确认
    else 额度可读
      ZCode-->>Service: 套餐与按模型额度
      Note over Service: capabilities 决定模型全集
    end
    Service->>ZCode: 读取客户端配置补全能力
    alt 客户端配置不可读
      ZCode-->>Service: 失败原因
      Note over Service: 容量与思考等级用保守默认值，并在界面说明
    end
    Note over Service: 按隐藏偏好过滤后重建供应商 profile
  end
  Service-->>Routes: 目录快照、额度、获取时间与降级说明
  Routes-->>UI: 账号状态、模型目录、按模型额度
```

### 模型目录卡片

目录卡片自身固定高度，只有模型列表区内部滚动；卡片头部与工具栏（搜索框、计数、刷新）不随列表滚动，长目录不会把整页撑高。

| 列表项 | 内容 |
| --- | --- |

| 容量 | 上下文窗口与最大输出；来自上游客户端配置或保守默认值 |
| 能力 | 思考等级、图片输入、工具调用；未声明时显示为不可用 |

### 额度卡片

Start Plan 的额度粒度是「模型 × 周期」，卡片按此组织，不合并成一个总百分比：

| 列 | 内容 |
| --- | --- |
| 模型 | 额度条目对应的模型显示名（如 `GLM-5.3`）；没有 capability 的账号级条目单独标注 |
| 周期 | 上游原样（`daily` / `one_time` 等），不翻译成自定义窗口名 |
| 用量 | 已用百分比、剩余量；总量为 0 时显示 0% 而不是无效数值 |
| 重置 | 有周期结束或到期时间时显示倒计时，并随时间递减 |

本账号的两份套餐分别提供日额度（GLM-5.3 3,000,000、GLM-5.3-Flash 5,000,000）与一次性活动额度（GLM-5.3 200,000,000、GLM-5.3-Flash 300,000,000），因此同一模型会出现两个窗口——这是预期展示，不是重复数据。

### 用量胶囊

胶囊位于对话输入区右侧，与其它状态控件同行，不遮挡输入框。三种策略的切换关系如下：

```mermaid
stateDiagram-v2
  [*] --> auto
  auto --> always: 用户选择常驻
  always --> auto: 用户改回自动
  auto --> off: 用户关闭
  off --> auto: 用户改回自动
  always --> off: 用户关闭
  off --> always: 用户选择常驻
  note right of auto: 仅在选中 ZCode 模型时显示
  note right of off: 隐藏并停止自动刷新
```

- `auto`：默认值。只在当前选中的模型属于 `ZCode` 供应商时显示；其它供应商模型不显示，也不触发额度请求。
- `always`：只要插件已登录就常驻显示，与当前选中的供应方无关；没有额度数据时显示未知或未订阅，不补 0%。
- `off`：完全不显示，并停止额度自动刷新；详情页额度卡片不受影响，仍可手动刷新。

策略变化在宿主侧持久化，下一次进入会话或下一次对话即按新策略显示，无需重启 DSH。

### 执行通道

选中 `ZCode` 模型后，DSH 会话与托管的 agent 子进程按以下规则协作：

| 关注点 | 行为 |
| --- | --- |
| 先决条件 | 客户端 CLI、内置 provider 配置、可写数据目录与已登录账号四者齐备；缺任一项给出可读原因并终止本轮 |
| 启动 | 首次取流时 spawn `zcode app-server`，后续请求复用同一进程；进程退出后下一次调用自动重建 |
| 账号注入 | 按家族注入 `account:<family>-start-plan`，`basedOnZCodeBuiltinRevision` 使用实际加载文件的 revision 与绝对路径摘要 |
| 会话 | 每个 DSH 会话对应一个 agent 会话；`setMode(yolo)` 让 agent 工具不卡在批准上；模型或思考等级变化时重新 `setModel` |
| 回合 | 同一会话串行；提交前垫时避免回合被丢弃；撞上未释放的锁时补 `session/stop` 后重试一次 |
| 上下文 | 首轮压平整段对话并附「工具归属」规则，后续只提交最后一条用户消息；图片以本地路径清单交付 |
| 输出 | 文本与思考增量转成 DSH chunk；伪 `antml` 调用标记被拦截并给出说明；用量来自 `turn.completed` |
| 收尾 | 回合失败、超时、中止与进程退出都补发 `session/stop`；失败以错误结束，不产生空白回复 |
| 标题 | 本地从标题请求携带的 JSON 数组里取第一条人话；取不到时保留默认标题、不产出文本块、不调用模型 |

思考等级按 `off` / `minimal` / `low` → `low`、`medium` / `high` → `high`、`xhigh` / `max` → `max` 归并；该端点没有「不思考」档，因此 `off` 也落到 `low`。换模型或换思考等级会在既有会话上重新 `session/setModel`。

DSH 侧的工具与批准流程不参与该回合：用户要求执行 DSH 工具时，结果取决于 ZCode agent 自己是否具备等价能力。说明页必须写明这一点，避免被理解为「DSH 工具失效」。

### 文案与命名

- 供应商名称固定为 `ZCode`，路由 id 固定为 `dsh-zcode`。
- 账号家族名称固定为 `BigModel`（国内）与 `Z.ai`（海外）；需要说明差异时写「授权页域名不同」，不写成「两套账号体系」。
- 额度窗口按上游周期名与模型名表达，例如「GLM-5.3 · 每日」「GLM-5.3 · 一次性」；不混用「日额度」「活动额度」之外的别名。
- 上游限制使用业务码与原文短语（`request has been blocked due to unusual activity.`、`model not allowed`），不翻译成模糊的「网络问题」或「权限不够」。托管通道可用后，`3012` 只作为兜底诊断出现（表示本次回合没有经过托管通道），不再写成「对话无法完成」。
- 执行通道的说明使用确定对象：写「ZCode 客户端自带的 agent 运行时」「ZCode agent 原生执行」，不写「本机」「代理」这类无法指代或与事实不符的说法。
- 「清单来源」按可信度说明是账号权益还是内置兜底；兜底时另附「未经账号确认」，不写成「降级」以免被理解为功能受损。

## 数据、权限和错误处理

### 持久化

| 数据 | 位置 | 权限 | 读取与恢复策略 |
| --- | --- | --- | --- |
| 账号凭据（账号 JWT、家族访问令牌、账号信息与家族） | `$DSH_HOME/.dsh-zcode-auth.json` | 文件 `0600`，目录 `0700` | 只由插件宿主读写；解析失败或格式版本不符时按未登录处理并给出可诊断错误，不覆盖原文件；凭据不含过期时间时不做本地过期判定，留 30 秒提前量处理已知过期的临界情况 |
| 插件偏好（胶囊策略、刷新间隔、隐藏模型） | `$DSH_HOME/.dsh-zcode-preferences.json` | 文件 `0600` | 缺失或损坏时回落到默认值；越界值夹到合法区间；隐藏模型按模型 id 记录 |
| 目录与额度快照 | 进程内存 | — | 目录与额度分别缓存；进程重启后重建，不落盘，避免把过期数据当成事实 |
| 桥接通道数据目录 | `$DSH_HOME/zcode-bridge/`（可用 `DSH_ZCODE_DATA_DIR` 覆盖）：`.zcode/v2/credentials.json`、`.zcode/v2/setting.json`、`.zcode/v2/provider_config.json`、`session.sqlite` 与 `workspace/` | 三份 JSON 文件 `0600`；目录由宿主按 umask 创建 | 每次取流前对账写入；不读写用户 `~/.zcode`；删除该目录等价于清空通道缓存与会话，不删除用户会话 |

### 权限

- 不新增 DSH 权限项，也不申请 fnOS 宿主权限；插件做宿主侧文件读写、对 `zcode.z.ai` 的出站请求，并以当前用户权限托管官方客户端自带的 agent 子进程。
- 同源 Web 路由只接受同源页面或回环地址发来的请求；跨站请求一律拒绝，凭据与目录响应不回显令牌。
- 凭据文件权限被放宽或属主不可读时，按共享包的既有判定给出可诊断错误，不静默忽略。
- 子进程只继承白名单环境变量（系统基础变量与 `ZCODE_*`），不整包透传宿主环境，避免其它供应商密钥进入子进程；`ELECTRON_RUN_AS_NODE` 一律删除。
- 桥接数据目录中的凭据按客户端同款 AES-256-GCM 加密，密钥由机器指纹派生（可用 `ZCODE_CREDENTIAL_SECRET` 覆盖）；插件不覆盖 `HOME`，保证子进程算出的指纹与宿主一致。

### 错误处理

| 场景 | 用户可见 | 恢复动作 |
| --- | --- | --- |
| 未登录 | 账号卡片显示两个家族的登录入口与说明 | 发起登录 |
| 授权取消或链接过期 | 回到未登录并说明原因 | 重新发起 |
| 登录接口不可达 | 账号卡片显示连接失败与账号家族 | 检查网络后重试 |
| 凭据缺失或已过期 | 账号卡片回到未登录并提示重新登录 | 重新登录 |
| 额度接口不可读 | 目录回退内置清单并标注未经账号确认；额度卡片显示未知与失败原因，不显示 0% | 刷新或稍后重试 |
| 客户端配置不可读 | 模型仍可用，容量与思考等级使用保守默认值并说明 | 刷新 |
| 账号权益里没有可用模型 | 回退内置清单并说明账号可能未订阅 Start Plan | 在 ZCode 侧确认套餐后刷新 |
| 参数错误（`3001`） | 会话或卡片显示上游原文与说明；设备标识异常时提示重新登录以恢复 | 重新登录 |
| 模型未授权（`3006`） | 会话显示 `model not allowed` 与「当前账号无该模型权益」的说明；不自动换模型 | 刷新目录确认权益 |
| 风控拦截（`3012`） | 说明本次回合没有经过托管通道（仍走 HTTP 直连或通道不可用）；保留上游原文，不自动重试、不伪装成功 | 确认 ZCode 客户端可用并重新发送；插件不提供绕过方式 |
| 未找到 ZCode 客户端 CLI | 会话显示「未找到 ZCode 客户端自带的 CLI（zcode.cjs）」，并提示安装客户端或用 `DSH_ZCODE_CLI` 指定 | 安装客户端或指定 CLI 路径后重试 |
| 未找到内置 provider 配置 | 会话提示客户端安装不完整（缺少 `zcode-builtin.json`）并给出探测到的路径 | 重新安装完整客户端 |
| 桥接数据目录不可写 | 会话显示写入失败的具体路径与系统错误 | 调整 `DSH_ZCODE_DATA_DIR` 或目录权限后重试 |
| 回合超时（默认 15 分钟） | 会话显示超时；插件补发 `session/stop` 释放回合锁 | 重发或新开会话 |
| 撞上未释放的回合锁 | 插件补发 `session/stop` 后重试一次；仍失败时显示「上一轮仍在运行」 | 稍后重试或新开会话 |
| agent 子进程退出 | 在途回合立即以错误结束，并提示下次调用会自动重建会话 | 直接重发 |
| 模型不在 agent registry | 日志记录 `setModel` 失败；回合可能落到会话默认模型 | 检查客户端发行版本与目录模型 id，必要时升级客户端 |
| 需要人机校验（`3007`） | 会话显示上游原文与「需在官方客户端完成校验」的说明 | 在官方客户端完成校验后重试 |
| 额度耗尽（`1113`） | 会话显示上游原文与额度状态；额度卡片同步反映已用比例 | 等待额度周期重置 |
| 用户手工配置了同名 `dsh-zcode` | 详情页说明冲突来源与处置方式；插件不注册、不覆盖用户配置 | 用户移除同名配置后重试 |
| 网络不可直达 `zcode.z.ai` | 各卡片显示连接失败 | 检查网络后重试 |

### 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **执行通道依赖本机 ZCode 客户端发行包** | 未安装、布局变化或版本升级都可能导致通道不可用，用户可能误以为是插件缺陷 | CLI 支持候选路径与 `DSH_ZCODE_CLI` 显式指定，provider 配置兼容两种发行布局；缺失时给出可读诊断并停止，不退回 HTTP 直连 |
| 通道的三个静默失败前提 | 数据目录只读、revision 不匹配或提交过快都会表现为「回合一直 running / 模型不在 registry」，且不报错 | 每次启动对账数据目录与三份文件；revision 直接对实际加载文件取摘要；提交前垫 2s / 1.5s / 1.5s；单测固定这些行为，日志保留关键节点 |
| 官方 agent 运行时的协议字段可能随版本漂移 | 反向请求、事件名或注入参数变化会让通道失效 | 协议客户端按最小可用语义应答未知反向请求；事件按类型白名单消费；发行包升级后以实账号冒烟验证并更新文档 |
| 一个 agent 会话同时只允许一个在途回合 | 并发发送或上一轮异常会撞锁，表现为「已在运行」 | 按 DSH 会话串行化；撞锁补 `session/stop` 后重试一次；失败、超时、中止与进程退出都在 `finally` 补 stop |
| 工具由 ZCode agent 原生执行 | 用户以为 DSH 工具会在该回合生效，实际不会 | 首轮注入「工具归属」硬规则；说明页写明该通道不使用 DSH 工具与批准流程；伪调用标记被拦截并解释 |
| 官方上游策略可能变化 | 直连限制或通道行为调整会影响可用性 | 不做针对规则的正向适配；诊断按业务码分层，变化时只更新文案与说明页 |
| 额度接口强制要求稳定设备标识 | 标识变化会让同一账号被当成新设备，反复要求重新授权 | 首次生成后缓存为进程内稳定值，并支持注入已保存值；用例覆盖同一进程内多次请求的一致性 |
| `X-Device-Mid` 缺失返回 `3001`，易被误判为代码缺陷 | 排查成本高 | 客户端把 `3001` 单独归类为参数错误并在诊断里点明设备标识；单测用缺少该头的响应夹具固定行为 |
| 模型清单来自账号权益，字段漂移会改变可用模型 | 目录与额度解析失败 | 模型全集有内置兜底；解析层以夹具固定已知形态，失败时降级并说明，不抛错到界面 |
| 额度按「模型 × 周期」表达，与固定三窗口的直觉不同 | 用户把两个窗口看成重复数据 | 卡片按模型与周期分列并标注周期原文；说明页写明日额度与一次性额度并存的正常性 |
| 账号 JWT 不带 `exp` | 无法在本地预判过期 | 上游给出时间才判定并留 30 秒提前量；未给出时以请求失败为准并提示重新登录 |
| 思考等级映射有损（上游只有三档） | 用户选的等级与上游档位不是一一对应 | 按 `off` / `minimal` / `low` → `low`、`medium` / `high` → `high`、`xhigh` / `max` → `max` 归并；未声明思考时只保留关闭档；说明页写明映射，不暴露不存在的档位 |
| 两个家族的授权页域名不同 | 用户选错家族后拿不到令牌 | 账号卡片写明国内 / 海外差异；登录失败时提示可切换家族重试 |
| 运行环境无法直连 `zcode.z.ai` | 登录、目录与请求全部不可用 | 明确提示连接失败并停止重试；不内置代理，不静默回退到其它供应商 |
| 凭据文件格式漂移 | 旧文件导致插件无法启动 | 落盘文档带版本与字段白名单，未知字段直接拒绝而不静默忽略；失败时按未登录处理且不覆盖原文件 |
| npm 上目标版本已被占用 | 发布失败 | 发布前核对目标版本，必要时先推进版本 |

### 决策

| 决策 | 选择 | 否决方案 | 原因 |
| --- | --- | --- | --- |
| 登录形态 | 只有 OAuth 设备授权，两个家族各一个入口 | 同时提供 API Key 登录 | Start Plan 的模型请求只接受账号身份，Key 形态没有可用路径；给出入口只会让用户走进死胡同 |
| 供应商路由名 | 唯一路由 `dsh-zcode`（显示名 `ZCode`） | 用 `zcode` / `zhipu` | 这两个名字可能已被用户在内置目录里手工声明；`dsh-` 前缀避开用户配置 |
| 模型清单真源 | 账号权益（额度条目的 `capabilities`） | 内置静态清单；或客户端配置里的模型表 | 权益是唯一能反映套餐变体、活动赠送与到期的来源；静态表会立刻过期。客户端配置只用于补全能力 |
| 权益不可读时的行为 | 回退内置清单并把来源标记为未经账号确认 | 直接展示空目录；或报错阻断 | 空目录会让选择器出现空分组；内置清单至少保留结构，配合来源说明不误导用户 |
| 额度粒度 | 按「模型 × 周期」分列 | 合并成单一总百分比 | 日额度与一次性活动额度可能同时存在，合并会掩盖「日额度用完但活动额度还有」的实际情况 |
| 思考等级映射 | 上游三档（low / high / max）：`off` / `minimal` / `low` → `low`、`medium` / `high` → `high`、`xhigh` / `max` → `max` | 把 pi-ai 的七个等级原样透传 | 上游端点只认三档且没有「不思考」档，透传未支持的值会得到 400 |
| 设备标识 | 首次生成后进程内稳定，可注入已保存值 | 每次请求新生成 | 额度接口要求稳定标识，否则同一账号被当成新设备并反复要求重新授权 |
| Start Plan 执行通道 | 托管官方客户端自带的 agent 运行时（`zcode app-server`），由它自行构造并签名请求 | 在 Node 侧复刻请求与签名；自行内置代理或反向代理转发 | 实测证明直连 HTTP 恒被 `3012` 拦截，而复刻签名所需能力在开源版被裁掉；托管官方运行时是让请求由官方客户端身份发出的可行路径，且不需要逆向或伪造 |
| 通道数据目录 | DSH home 下的插件自有目录 `zcode-bridge`，每次启动对账 | 复用桌面端 `~/.zcode`；读取桌面端登录态 | `~/.zcode` 可能只读，只读时回合会静默卡住；复用桌面端状态还会把插件与用户客户端耦合 |
| 通道凭据 | 插件自己的 OAuth 令牌按客户端同款 AES-256-GCM 写入桥接目录 | 复制桌面端 `credentials.json`；明文存放 | 不依赖桌面端是否登录过，也不越过插件自己的登录流程；文件仍是加密形态 |
| 会话标题 | 本地生成，取不到人话时回退默认标题 | 调模型起名；照抄标题请求里的英文指令 | 起名会消耗额度；照抄会把英文指令变成标题（实测事故） |
| 失败呈现 | 区分业务码分别提示 | 统一显示「调用失败」 | `3006`、`3007`、`3012`、`1113` 的处置完全不同，笼统提示会让用户做错动作 |
| 界面承载方式 | 插件详情页自定义区块 | 设置弹框的官方配置表单 | 账号、额度与目录都是交互型区块，官方配置 schema 表达不了（按插件 UI 规范第 2 档） |
| 市场索引维护 | 只加源列表，发布后重生成 | 手工改写生成的索引文件 | 索引由官方生成器从 npm 产物读取，手改会与源列表漂移 |

- **DSH Web**：`pnpm run start -- --web`（`DSH_HOME` 指向仓库 `.dsh`），用启动日志里带 token 的地址访问；运行环境需安装 ZCode 客户端（或用 `DSH_ZCODE_CLI` 指定），覆盖两个家族的登录、权益目录、能力字段、按模型额度、胶囊策略，以及文本 / 图文 / 思考等级三轮端到端对话。走查证据：纯文本回合 18 秒回复「通道可用」；图文 + High 15 秒完成、吞吐 256 tok/s、缓存命中 28%；用量胶囊由「剩余 100%」变为「剩余 93% · 6 小时后重置」。日志中应出现「Start Plan 账号已注入」与「新建 agent 会话」。
- **DSH Desktop**：使用上游检出的开发态 Desktop（`fork-pj/deepseek-harness`），通过渲染进程调试端口取证；重点核对系统浏览器打开授权页、目录卡片固定高度与滚动、胶囊位置与亮暗主题，以及桥接通道在同一 profile 下的可用性（**尚未执行，结果按待执行登记**）。
- **文档站**：`pnpm run check -- --docs`（或 `pnpm run build -- --docs`、`pnpm exec vitepress build docs`）与 `git diff --check`；逐项核对新增菜单与页面链接目标存在。
- **打包与发布**：按仓库版本流程更新版本（功能提交与版本提交分开），随后发布插件；发布后重新生成市场索引，并登记到应用发布清单。**发布说明需写明 Start Plan 通道依赖本机 ZCode 客户端、工具由 ZCode agent 原生执行**，避免用户按「任意环境可用」预期安装。
- **回滚**：停用或卸载插件即可撤销 `ZCode` 供应商注册，模型选择器回到手工配置方式；说明页、插件总览行、菜单条目与市场源列表按提交回退。插件自有的凭据与偏好文件只有用户明确要求时才删除。
- **禁止删除**：用户会话历史、其它供应商的凭据与配置；本插件不持久化目录与额度，无需清理这两类数据。
