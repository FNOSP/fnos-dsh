## 计划目标

按 [FNOS-060](/requirements/FNOS-060-mobile-icon-only-search-toggle) 把消息框左下角的「智能搜索」开关在移动设备上收成图标态：不渲染可见文案，按钮几何收成 28×28，图标居中，配色与开关行为不变。

技术边界：只改控件自身的呈现推导、组件渲染与按钮几何样式；不动会话级状态读写、端点、乐观更新/回滚链路，也不动其它控件。

## 当前实现与目标设计

| 领域 | 当前实现 | 目标实现 | 迁移影响 |
| --- | --- | --- | --- |
| 控件形态 | 固定渲染地球图标 + 「智能搜索」文本节点 | 判为移动设备时不渲染文案，只留图标位 | 桌面端渲染结果与改动前一致 |
| 呈现推导 | 类名在 `className` 三元里内联拼接 | 抽到纯函数 `togglePresentation`，返回类名与文案可见性 | 单测有了真正的行为落点（不再是源码字符串断言） |
| 设备判定 | 无 | 取宿主 `@deepseek-ai/dsh-client-ui-primitives` 的 `isMobileDevice()` | 与官方控件同一口径；页面生命周期内缓存，无重复开销 |
| 几何 | 28px 高、`0 8px` 内距、宽度随文案 | 新增 `--iconOnly` 修饰类：`width: 28px`、`padding: 0`、图标居中 | 命中区仍是 28×28，行高不变 |
| 可访问名称 | `aria-label` 由纯函数按状态生成 | 不变 | 收起文案不影响名称 |

## 架构与数据流

控件仍是 `conversation.input.left` 座位上的一个按钮，数据流未变：

1. 座位按会话注入 `sessionId`，组件经插件端点读取该会话的开关状态（失败保持默认开启）。
2. 点击先乐观更新，再用端点返回值校正，失败回滚。
3. 新增的只有**呈现层**：渲染时调用 `isMobileDevice()` 得到设备判定，与当前状态一起交给 `togglePresentation`，得到「类名 + 是否渲染文案」。

设备判定不参与状态存储，也不改变任何请求；它只决定 DOM 里有没有那段文案、按钮用哪套几何。

## 交互和行为设计

- **入口**：消息框左下角控件行，与「工作区内修改」「深度思考」同一行；位置不变。
- **移动端状态**：只有 14px 地球图标。开启（默认）时浅蓝底 + 蓝色图标，关闭时透明底 + 次级灰图标。按钮 28×28，与官方 `+` 控件同尺寸，图标居中。
- **桌面端状态**：地球图标 + 「智能搜索」文案，几何与配色与改动前一致。
- **点击**：命中区与之前相同（至少 28×28），点击仍切换该会话开关；写入期间禁用与 60% 透明度沿用。
- **键盘与读屏**：`tab` 可达，名称仍为「智能搜索：已开启，点击关闭」/「智能搜索：已关闭，点击开启」，`aria-pressed` 表达状态。
- **升级前后**：无配置、无持久化字段变化；桌面端用户看不到任何差异，移动端用户看到同一按钮变成图标。
- **破坏性操作**：不涉及。

## 数据、权限和错误处理

- 不新增持久化数据、不新增请求、不涉及凭据；开关状态仍只存宿主内存。
- 读取状态失败保持默认开启（既有行为）；写入失败回滚（既有行为）。
- 移动设备判定失败或识别不了 UA 时按桌面处理：显示文案，等于回退到旧形态，不阻塞使用，也不产生错误提示。

## 依赖、风险和决策

| 项 | 说明 | 处置 |
| --- | --- | --- |
| 依赖 | 宿主 primitives 的 `isMobileDevice` 公共导出（0.2.2-rc.5 已核实；插件 `engines.dsh` 基线即是 rc.5） | 不新增依赖、不加兼容垫片 |
| 决策：设备级 vs 视口级 | 采用设备级判定：桌面窄窗口保持文案，与官方控件的移动行为同口径；横竖屏切换不抖动 | 视口/容器规则列为明确不在本次范围 |
| 风险：极少数内嵌浏览器识别不出移动 UA | 仍显示文案（旧形态），功能可用 | 不阻塞；如需要另立需求用容器宽度兜底 |
| 风险：图标态信息量下降 | 新用户可能不认得地球图标代表什么 | 沿用官方地球图标与既有配色；名称与交互不变 |
| 回退 | 删除条件渲染分支与 `--iconOnly` 类即可，两处互不影响；不涉及数据回退 |
